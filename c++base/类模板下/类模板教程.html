1先花一分钟回顾：类模板是什么

承上启下。别急着看新东西，先把地基踩实。

上一课我们把一个"只能装 int 的数组类"改造成了真正意义上的数组类——它能装任何类型。 做法就是在类前面加一行 template<typename T>，把写死的类型换成泛指类型 T：

回顾：一个单类型参数的类模板 
template<typename T>      // 声明一个泛指类型 T
class Array
{
    T* m_data;            // 里面装的是"某种类型"T，而不是写死的 int
    // ...
};

Array<int>    ai;         // 用的时候再告诉编译器 T 到底是什么
Array<double> ad;

上一课的结尾还提到了 类模板的特化。当时可能有同学心里犯嘀咕：

🤔
同学的灵魂拷问
"一个类模板特化之后，看起来不就变成两个类了吗？这么做有什么用、有什么意义？ 我直接再写一个新类不行吗？"

这一课，我们就来正面回答这个问题。而答案，藏在接下来的四个知识点里： 多类型参数 → 偏特化 → 非类型参数 → 工程应用。走起。

2类模板可以有多个类型参数

函数模板能做的，类模板也能做。这一点几乎"免费"。

学函数模板时你就见过多类型参数了。既然函数模板是模板、类模板也是模板， 那么类模板同样可以定义多个类型参数。语法非常自然——尖括号里用逗号隔开就行：

example22-1.cpp · 两个类型参数的类模板 
template<typename T1, typename T2>   // 两个类型参数
class Test
{
public:
    void add(T1 a, T2 b)             // a 是 T1 类型，b 是 T2 类型
    {
        cout << (a + b) << endl;
    }
};

int main()
{
    Test<double, int> t;             // T1 = double, T2 = int
    t.add(10.0001, 8);               // double + int → double
    return 0;
}

使用时 Test<double, int> 就把 T1 定成 double、 T2 定成 int。10.0001 + 8 的结果自然是 double， 所以打印出 18.0001，和我们的预期一致。

3类模板的局部特化（偏特化）

      
全特化是"钉死所有类型"，偏特化是"只钉死一部分"。


      
上一课的特化（全特化）是把类型全部指定死。而这一课的局部特化 / 偏特化
      则是"只指定一部分、剩下的仍然保持泛型"。它本身还是一个模板。


      
为什么需要它？想想 Test<T1, T2> 里的 add：
      不同类型相加还好；但如果两个数是同一种类型（这在工程里反而更常见），
      两个很大的 int 相加可能溢出，出于安全考虑我们想做一次强制类型转换。
      这时候就可以"针对两个类型相同的情况"写一个偏特化：


      
偏特化 ①：两个类型相同 Test<T, T>

      

        
偏特化：处理"两个类型相同"的情况
          


template<typename T>        // 仍然是模板！但只剩一个类型参数
class Test<T, T>            // 特化名后面写 <T, T>：两个参数一样
{
public:
    void add(T a, T b)
    {
        cout << "add(T a, T b)" << endl;
        cout << static_cast<T>(a + b) << endl;  // 相同类型：做一次强制转换更安全
    }
};

      


      

        
🔑

        

          注意开头仍是 template<typename T>——因为它还是一个模板；
          而类名后面的 <T, T> 才是"局部特化"的关键：它说的是"当两个类型参数恰好一样时，用我"。
        

      


      
偏特化 ②：第二个参数固定为 int Test<T, int>

      

        
偏特化：把 T2 钉死成 int
          


template<typename T>
class Test<T, int>         // 第一个仍泛型，第二个固定为 int
{
public:
    void add(T a, int b)
    {
        cout << "add(T a, int b)" << endl;
        cout << a + b << endl;
    }
};

      


      
偏特化 ③：两个都是指针 Test<T1*, T2*>

      
这是偏特化最"有意义"的一种：两个指针相加是没有意义的（a + b 会出错），
      所以我们为指针专门写一份，让它不做加法：

      

        
偏特化：专门伺候指针类型
          


template<typename T1, typename T2>
class Test<T1*, T2*>       // 两个参数都是"指针"
{
public:
    void add(T1* a, T2* b)
    {
        cout << "add(T1* a, T2* b)" << endl;   // 指针不做相加，避免出错
    }
};

      


      

        
🎯

        

          
这就回答了开头那个"灵魂拷问"

          有些类型（比如指针）不适合通用模板里定义的行为。解决办法有两种：
          ① 另写一个全新的类；② 写一个偏特化。二者本质相同，但偏特化的最大好处是——
          使用者始终以统一的方式 Test<...> 来用，
          由编译器自动挑选合适的版本，不用记"什么时候该用哪个类"。
        

      

    


    
    

      
4编译器怎么挑？——特化的选择规则

      
只有一条核心规则，再加一个"选不出来就报错"的边界情况。


      

        
📏

        

          
核心规则

          编译器永远优先选择更"特殊"的版本：偏特化 > 通用模板。
          如果有两个偏特化"特殊程度相当"、都能匹配，编译器无法抉择，直接报错（二义性）。
        

      


      
现在假设通用模板 Test<T1,T2> 和三个偏特化
      （<T,T>、<T,int>、<T1*,T2*>）同时存在，
      我们来逐个"审判"每一种用法。动手点点看：


      

        
🧪 互动演示：编译器会选中哪一个版本？

        
点一个实例化写法，看看谁会被选中、为什么。红色的是会导致编译报错的二义性情况。

        

          Test<double, int>
          Test<long, long>
          Test<float, int>
          Test<int, int>
          Test<int*, int*>
        

        

      


      

        
⚠️

        

          
两个"势均力敌"的偏特化会打架

          Test<int, int> 既满足 <T,T>（两个一样），又满足
          <T,int>（第二个是 int）；Test<int*, int*> 既满足
          <T,T>，又满足 <T1*,T2*>。这两种情况编译器都无法决定，会报二义性错误。
          课堂里老师的做法是：把 <T,T> 那份注释掉，
          把"讲台"让给专门处理指针的 <T1*,T2*>，程序就能顺利编译了。
        

      


      
下面是去掉 <T,T> 之后能顺利编译运行的完整版本。运行它，对照输出看看每个对象各自调用了谁：


      

        
example22-2.cpp · 偏特化的选择（可编译版）
          


template<typename T1, typename T2>      // 通用模板
class Test { public: void add(T1 a, T2 b){ cout<<"add(T1 a, T2 b)"<<endl; cout<<(a+b)<<endl; } };

// template<typename T> class Test<T, T> { ... };  // ← 注释掉，避免与 <T*,T*> 打架

template<typename T>                     // 偏特化：第二个是 int
class Test<T, int> { public: void add(T a, int b){ cout<<"add(T a, int b)"<<endl; cout<<(a+b)<<endl; } };

template<typename T1, typename T2>      // 偏特化：两个都是指针
class Test<T1*, T2*> { public: void add(T1* a, T2* b){ cout<<"add(T1* a, T2* b)"<<endl; } };

int main()
{
    int i = 0, j = 0;
    Test<double, int> t;    // → <T, int>
    Test<long, long>  ti;   // → 通用模板（long≠int，也不是指针）
    Test<float, int>  tt;   // → <T, int>
    Test<int*, int*>  tp;   // → <T*, T*>

    t.add(10.0001, 8);      // 18.0001
    ti.add(2, 3);           // 5
    tt.add(4, 5);           // 9
    tp.add(&i, &j);         // 指针版，不相加
    return 0;
}

        💼 插一句工程感悟：为什么"偏特化"比"另写一个新类"更好用？
        

          
设想你是公司里专门做底层类库的工程师。你写了一个类模板，它能处理大部分类型，
          但对指针不行。这时如果你另写一个新类，就得在 API 文档里叮嘱同事："某某情况下请用这个新类"。
          可惜——不是每个人都会记得、都会看文档，于是 bug 就来了。

          
而偏特化让使用者始终写 Test<...>，
          编译器自动挑选实现。对外只有"一个类模板、一种用法"，用起来非常舒服。
          写库时的用户友好度，往往决定了这套库能不能推广开——这一点在实际工程中至关重要。

        

      

    


    
    

      
5非类型模板参数：模板还能传"数值"

      
模板参数不一定是"类型"，也可以是一个具体的"数值"。


      
到目前为止，模板参数都是类型（typename T）。但其实模板参数
      也可以是一个具体的数值，比如一个 int。看这个函数模板：


      

        
example22-3.cpp · 非类型模板参数
          


template<typename T, int N>      // 第一个是类型参数，第二个是"数值参数" N
void func()
{
    T array[N] = {0};            // 用 N 指定栈上局部数组的大小！

    for(int i = 0; i < N; i++)
    {
        array[i] = i + 1;
        cout << array[i] << " ";
    }
    cout << endl;
}

int main()
{
    func<int,   5>();             // 一个大小为 5  的 int   数组
    func<float, 10>();            // 一个大小为 10 的 float 数组
    return 0;
}

      


      
是不是很酷？我们用 N 在编译期动态指定了一个栈上局部数组的大小。
      func<int, 5>() 得到一个 5 元素的数组，func<float, 10>() 得到 10 个。

6一道面试题：让编译器替你算 1+2+…+N

      
真实面试故事。把"非类型参数 + 特化 + 递归"三件武器合起来用。


      

        
🎙️

        

          
题目的来历

          面试时问应聘者："用程序求 1 加到 N 的和，怎么写最快？"
          他先说 for 循环，又改进成等差数列公式（O(1)）……但公式里有加法、还有除法，仍有运行时开销。
          最快的答案是：让编译器在编译期就把结果算好，运行时开销为零。
        

      


      
预备知识：类内的静态常量

      
C++ 允许在类里直接写一个 static const 整型常量并就地初始化。
      因为 static 让它属于整个类（相当于全局），const 又让它进入符号表、
      不占运行时空间——它就是一个编译期就定好的字面常量：


      

        
类内静态常量：编译期就定好的值
          


class Foo
{
public:
    static const int VALUE = 1;   // 只有 static const 整型能这样就地赋"字面常量"
};

      


      
把它做成模板 + 用递归思想拆解

      
求 1 加到 N，等于"1 加到 (N-1) 的和" 再加 N。这就是递归：
      Sum<N>::VALUE = Sum<N-1>::VALUE + N。
      递归必须有终点，所以再写一个 全特化 Sum<1> 告诉编译器"到 1 就停，值就是 1"：


      

        
example22-4.cpp · 编译期递归求和
          


template<int N>                 // 非类型参数 N
class Sum
{
public:
    static const int VALUE = Sum<N - 1>::VALUE + N;   // 递归：依赖 Sum<N-1>
};

template<>                      // 全特化：递归的终点
class Sum<1>
{
public:
    static const int VALUE = 1;                       // Sum<1> 就是 1，停止递归
};

int main()
{
    cout << Sum<10>::VALUE  << endl;   // 55
    cout << Sum<100>::VALUE << endl;   // 5050
    return 0;
}

      


      

        
🚫

        

          
没有 Sum<1> 这个特化会怎样？

          递归会一路 Sum<1> → Sum<0> → Sum<-1>… 永不停止，编译器直接报错。
          所以：编译期递归必须有一个特化来收尾。
        

      


      

        
🧪 互动演示：看编译器如何"递归展开" Sum<N>

        
选一个 N，看看编译期是怎样一层层展开、最后落到 Sum<1> 的特化上的：

        

          Sum<3>
          Sum<5>
          Sum<10>
          Sum<100>
        

        

        

      


      

        
⚡

        

          
为什么这是"最快"的？

          Sum<100>::VALUE 这个 5050 是编译器在编译时算好并写进符号表的。
          程序运行时只是读取一个常量——没有函数调用、没有加减乘除、零计算开销。
          这就是"让编译器替我们干活"的威力，在嵌入式等对效率敏感的场景很有用。
        

      

    


    
    

      
7非类型模板参数的限制

      
强大，但有边界。记住几条即可。


      
    
        
  • 变量不能作模板参数。模板参数必须是编译期常量表达式，
        像 int n = 5; func<int, n>() 这样用变量 n 会报错——
        "n 不是常量表达式"。前面例子里我们写的都是字面常量 5、10。
    • 
        
  • 浮点数、类对象、全局指针一般不能作模板参数。这更多是历史原因；
        实践中，用整型（int）做非类型参数是最安全、最可靠的选择。
    • 
        
  • 推导发生在编译期。正因为在编译期完成，运行时才没有开销；
        也正因为如此，递归必须靠特化来收尾，否则编译器推导永远停不下来、直接报错。
    • 
      


      

        
📌

        

          
一句话记住

          非类型模板参数 = 编译期就要确定的常量。首选 int，
          用变量必报错，递归要有特化终点。

8工程实战：手写一个智能指针

      
把类、模板、构造/析构、运算符重载全部串起来的综合应用。


      

        
🐛

        

          
工程里最怕什么？内存 bug

          经验之谈：实际工程里约 90% 的 bug 都和内存误操作相关，主要三类：
          ①内存泄漏（new 了没 delete）、②多次释放（delete 两次以上）、
          ③越界（申请 10 字节却用了 20）。越界一般用数组类（重载 [] 检查下标）解决；
          泄漏与多次释放，则交给智能指针。
        

      


      
智能指针的设计思路

      
智能指针本身是一个类模板，核心思想是用对象的生命周期来管理堆内存：

      
    
        
  1. 接管堆内存：通过构造函数拿到并保存那块 new 出来的堆内存指针。
    2. 
        
  2. 自动释放：通过析构函数 delete 掉它——对象一销毁，内存就还回去，杜绝泄漏。
    3. 
        
  3. 用起来像指针：重载 operator* 和 operator->，模拟指针的解引用与成员访问。
    4. 
      


      
声明：SmartPointer.h

      

        
SmartPointer.h · 类模板的声明
          


#ifndef _SMARTPOINTER_H_
#define _SMARTPOINTER_H_

template<typename T>
class SmartPointer
{
protected:
    T* m_pointer;                       // 被托管的堆内存指针
public:
    SmartPointer();                     // 无参：默认指向空，安全
    SmartPointer(const T* pointer);     // 接管一块堆内存
    ~SmartPointer();                    // 析构时自动释放
    T* operator->();                    // 模拟 ->（成员访问）
    T& operator*();                     // 模拟 * （解引用）
};

#endif

      


      
实现：SmartPointer.hpp

      

        
SmartPointer.hpp · 类模板的实现
          


#ifndef _SMARTPOINTER_DEF_H_
#define _SMARTPOINTER_DEF_H_

#include "SmartPointer.h"

template<typename T>
SmartPointer<T>::SmartPointer()
{
    m_pointer = NULL;                   // 默认空，避免野指针
}

template<typename T>
SmartPointer<T>::SmartPointer(const T* pointer)
{
    m_pointer = const_cast<T*>(pointer);  // 接管这块堆内存（去掉 const）
}

template<typename T>
SmartPointer<T>::~SmartPointer()
{
    delete m_pointer;                   // 关键：析构时自动释放
}

template<typename T>
T* SmartPointer<T>::operator->()
{
    return m_pointer;                   // p->member 等价于 m_pointer->member
}

template<typename T>
T& SmartPointer<T>::operator*()
{
    return *m_pointer;                  // *p 等价于 *m_pointer
}

#endif

      


      

        
📁

        

          
为什么模板的实现放在 .hpp？

          模板的完整定义必须对使用它的地方"可见"，因此通常把声明与实现都放进头文件
          （这里用 .h + .hpp 拆开只是组织习惯），
          使用者 #include "SmartPointer.hpp" 即可。
        

      


      
用起来：和普通指针几乎一模一样

      

        
example22-5.cpp · 使用智能指针
          


#include "SmartPointer.hpp"

class Test { public: int i; void print(){ cout << i << endl; } };

int main()
{
    SmartPointer<int>  pi = new int(5);     // 像指针一样"指向"堆上的 int
    SmartPointer<Test> pt = new Test();     // 指向堆上的 Test 对象

    cout << *pi << endl;     // 5   —— 重载 * 解引用
    *pi = 10;
    cout << *pi << endl;     // 10

    pt->i = 20;             // 重载 -> 访问成员
    pt->print();            // 20

    return 0;               // 注意：这里没有 delete，却不会泄漏！
}

      


      

        
✅

        

          
没写 delete，为什么不会泄漏？

          pi 和 pt 是栈上的对象，
          main 结束时它们的析构函数会被自动调用，
          析构函数里 delete m_pointer; 就把托管的堆内存释放了。
          用它，就"最大限度地"避免了内存泄漏和多次释放——这就是智能指针的价值。

要点一句话记住

        
多类型参数类模板和函数模板一样，可以有多个类型参数：Test<T1, T2>。

        
偏特化只钉死一部分类型（如 <T,T>、<T,int>、<T*,T*>），它本身还是模板。

        
选择规则编译器优先选更特殊的偏特化；两个偏特化势均力敌则报二义性。

        
偏特化的意义让使用者统一以一种方式使用，由编译器自动挑实现——比另写新类更友好。

        
非类型参数模板参数也能是数值（如 int N），首选整型，必须是编译期常量。

        
编译期计算"非类型参数 + 特化 + 递归"可让编译器在编译期算好结果，运行时零开销。

        
工程应用数组类防越界、智能指针防泄漏/多次释放——它们都是类模板。
