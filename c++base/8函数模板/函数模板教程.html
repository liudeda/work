1为什么需要模板？先从一个痛点说起

一切设计都是为了解决问题。模板要解决的，是"重复代码"的问题。

我们几乎每天都会写这样一个交换两个变量的小函数。在 C++ 里用引用能优雅地做到这一点：

交换两个 int 
void Swap(int& a, int& b)   // 交换两个 int
{
    int t = a;
    a = b;
    b = t;
}

可是当你要交换 float、交换指针、交换你自己写的类……你会发现自己在不停地复制粘贴：

同样的逻辑，写了一遍又一遍 
void Swap(float& a, float& b)     // 交换两个 float
{
    float t = a; a = b; b = t;
}

void Swap(char& a, char& b)       // 交换两个 char
{
    char t = a; a = b; b = t;
}

void Swap(Student& a, Student& b) // 交换两个自定义类型……还有成百上千种
{
    Student t = a; a = b; b = t;
}
🤔
看出问题了吗？
这几个函数算法完全一样（借助临时变量交换），唯一的区别只是数据类型不同。 如果我们自定义了成百上千种类型，难道要写成百上千个一模一样的 Swap？ 这既枯燥乏味，又让代码极度冗余。

C++ 一直强调代码复用。那么——有没有一种办法，让我们只写一次逻辑，就能应付所有类型？ 有。它的名字叫模板。但在讲模板之前，我们要先认识一个"听起来很高大上、其实是纸老虎"的概念。

2什么是泛型编程？（一只纸老虎）

名字唬人，本质极简。

泛型编程（Generic Programming）的本质，就是一句话：

🧩
不考虑具体数据类型的编程模式。
解决问题时，先只想"方法/算法"，而暂时不管数据到底是 int、 double 还是某个自定义类。

其实你早就用过它了。学数据结构时，我们设计一个排序算法，一开始会关心"数组里装的是整数还是字符"吗？ 不会——我们只关心怎么排。这，就已经是泛型思想了。

"泛型"二字，即 泛指的 类型 —— 广泛的、不特指某一种的数据类型。 我们用一个字母 T（Type 的首字母）来代表这个"泛指的类型"，于是 Swap 的泛型写法长这样：

泛型写法（还差一步，编译器暂时不认识 T） 
// 只考虑"如何交换"，不考虑 T 具体是什么类型
void Swap(T& a, T& b)
{
    T t = a;   // 申请一个"相同类型"的临时变量
    a = b;
    b = t;
}
⚠️
上面这段代码编译不过！因为编译器不认识 T 是什么。 T 就像一个"类型版的函数参数"：它代表某个类型，但具体是哪个还没指定， 要等到真正调用时才确定。下一章我们就给它"上户口"。

3函数模板的语法：template 与 typename

两个关键字，给 T "上户口"。

要让编译器认识 T，只需在函数前面加一行"声明"：

example20-1.cpp · 一个完整的函数模板 
template<typename T>      // ← 关键的一行
void Swap(T& a, T& b)
{
    T t = a;
    a = b;
    b = t;
}

这一行由两个关键字组成，各司其职：

关键字作用
template告诉编译器："老兄，从现在开始我要进行泛型编程了，后面出现的类型名你别乱报错。"
typename T在尖括号里声明一个泛指的类型 T。它不是某个具体类型，而是一个"类型占位符"。
📝
小知识
尖括号里的 typename 也可以写成 class，二者在这里等价： template<class T> 完全合法。名字 T 只是习惯，你叫 AnyType 也行。

现在再回头看这段代码就通透了：template 宣告"要泛型了" → typename T 声明"泛指类型 T" → 下面的函数体用 T 描述了对任意类型都通用的交换方法。恭喜，你已经学会写函数模板了！

4如何使用它？两种调用方式

让编译器自动推导，或者你亲自指定。

方式一：自动类型推导

直接像调用普通函数一样调用它，编译器会根据实参类型自动推断 T 是什么：

自动推导 
int a = 1, b = 2;
Swap(a, b);   // 实参是 int → 编译器推导出 T = int

方式二：显式指定类型

在函数名后用尖括号亲自告诉编译器 T 用哪个类型：

显式指定 
float fa = 3, fb = 4;
Swap<float>(fa, fb);   // 明确告诉编译器：把 T 替换成 float
🔎
无论哪种方式，调用过程和普通函数没有任何本质区别：一样压栈传参、一样返回。 区别仅在于——是让编译器猜类型，还是你直接摊牌。

完整示例（配套源码 example20-1）

      
一份 Swap 模板，同时服务 int、float、char。点 ▶ 运行 看看结果：


      

        
example20-1.cpp
          


#include <cstdlib>
#include <iostream>
using namespace std;

template<typename T>
void Swap(T& a, T& b)
{
    T t = a;
    a = b;
    b = t;
}

int main()
{
    int a = 1, b = 2;
    Swap(a, b);                 // 自动推导 T = int
    cout << "a = " << a << endl;
    cout << "b = " << b << endl;

    float fa = 3, fb = 4;
    Swap<float>(fa, fb);        // 显式指定 T = float
    cout << "fa = " << fa << endl;
    cout << "fb = " << fb << endl;

    char ca = 'a', cb = 'b';
    Swap(ca, cb);               // 自动推导 T = char
    cout << "ca = " << ca << endl;
    cout << "cb = " << cb << endl;
    return 0;
}

      


      

        
🎉

        

          成就时刻：你只写了一个 Swap，它却能在 int、float、
          char 之间自由切换。放在过去，这得写三个几乎一样的函数。
        

      

    


    
    

      
5进阶：写一个"泛型算法"（选择排序）

      
名字很唬人，本质还是那套：只写一次，通吃所有类型。


      
既然函数可以泛型，算法当然也可以。我们用泛型的方式写一个选择排序：排序时只关心元素间的
      大小关系，完全不管它是 int 还是 char。


      
    
        
  • 声明泛型：template<typename T>，数组元素类型为 T。
    • 
        
  • 外层循环确定每一趟要放"最小值"的位置 i。
    • 
        
  • 内层循环从 i+1 往后扫，记录最小值 min 与它的下标 index。
    • 
        
  • 复用 Swap：把找到的最小元素换到前面 —— 之前写的 Swap 模板正好派上用场！
    • 
      


      

        
example20-2.cpp
          


template<typename T>
void Swap(T& a, T& b) { T t = a; a = b; b = t; }

template<typename T>
void SelectSort(T array[], int length)
{
    for (int i = 0; i < length; i++)
    {
        T   min   = array[i];
        int index = i;
        for (int j = i + 1; j < length; j++)
        {
            if (array[j] < min)   // 只关心"谁更小"，不关心具体类型
            {
                min   = array[j];
                index = j;
            }
        }
        Swap(array[i], array[index]);  // 复用泛型 Swap
    }
}

int main()
{
    int array[] = {3, 2, 5, 3, 4};
    SelectSort<int>(array, 5);          // 显式指定，可读性更好

    char ca[] = {'b', 'c', 'a', 'e', 'd', 'f'};
    SelectSort(ca, 6);                  // 自动推导也完全可以
    return 0;
}

      


      

        
🚀

        

          
这才是真正的代码复用

          一个 SelectSort 写完之后，无论 int 数组、char 数组、
          还是任何支持 < 比较的类型数组，都能直接拿来用。
        

      


      

        
💬

        

          显式写 SelectSort<int>(...) 还是让编译器自动推导 SelectSort(...)？
          两者都对。显式写法可读性更好——一眼就知道处理的是什么类型，属于个人风格取舍。
        

      

    


    
    

      
6揭秘：编译器到底是怎么处理模板的？

      
别被模板的"外表"骗了。真相可能和你想的不一样。


      

        
🎭

        

          
一个常见误解

          很多人以为：模板 = 一个"神通广大、能处理任意类型"的函数，程序里始终只有一个函数存在。

          这是错的。
        

      


      
真相是：编译器会根据每一次调用用到的具体类型（无论自动推导还是显式指定），
      从模板"复制"出一个实实在在的、针对该类型的函数。这个过程叫模板实例化（instantiation）。


      
换句话说，那些冗余的、重复的函数并没有消失——只是从"你手写"变成了"编译器替你写"。
      我们把枯燥的体力活交给了编译器。


      
眼见为实：看看汇编里有几个 Swap

      
把 example20-1 编译成汇编（g++ -S example20-1.cpp）后去数一数，你会发现——
      源码里只有一个模板，汇编里却有三个 Swap 函数：


      

        
example20-1.s（汇编，示意）
          


_Z4SwapIiEvRT_S1_:    ; ← Swap<int>    (i 代表 int)
    ... 交换逻辑 ...
_Z4SwapIfEvRT_S1_:    ; ← Swap<float>  (f 代表 float)
    ... 交换逻辑（与上面几乎一模一样）...
_Z4SwapIcEvRT_S1_:    ; ← Swap<char>   (c 代表 char)
    ... 交换逻辑 ...

      


      
三次调用（int / float / char）就生成了三个函数，
      它们的函数体逻辑几乎完全相同，只是类型不同。这正好印证了：模板 = 一个"函数生成器"。


      

        
🧠

        

          
重要结论：编译器对模板会进行"两次编译"

          
    
            
  1. 第一次——在模板定义处，对模板代码本身做语法检查。
    2. 
            
  2. 第二次——在模板被调用处，用具体类型实例化出真正的函数，再对这个函数编译一次。
    3. 
          

          汇编里出现三个 Swap，正是"第二次编译"留下的证据。

7当函数模板遇上函数重载

      
同名了怎么办？记住三条规则就够了。


      
从使用者的角度，函数模板看起来就像一个特殊的函数。既然是函数，它就可能和一个同名的普通函数发生重载。
      来看配套源码 example20-3：


      

        
example20-3.cpp · 三个同名的 Max
          


int Max(int a, int b) {                 // ① 普通函数
    cout << "int Max(int a, int b)" << endl;
    return a > b ? a : b;
}

template<typename T> T Max(T a, T b) {  // ② 函数模板（两参数）
    cout << "T Max(T a, T b)" << endl;
    return a > b ? a : b;
}

template<typename T> T Max(T a, T b, T c) { // ③ 函数模板（三参数）
    cout << "T Max(T a, T b, T c)" << endl;
    return Max(Max(a, b), c);
}

      


      

        
📜

        

          
三条黄金规则

          
    
            
  1. 优先选普通函数：当普通函数能完全匹配时，优先调用它，而不是模板。
    2. 
            
  2. 模板能更好匹配时选模板：如果用模板能生成一个"更合适"的版本（避免类型转换），就选模板。
    3. 
            
  3. 空模板参数列表 <>：写 Max<>(...) 可强制只考虑模板，忽略普通函数。
    4. 
          

        

      


      
      

        
🧪 互动演示：猜猜编译器会调用哪一个？

        
点击下面每一个调用语句，看看编译器选择了谁、以及为什么。

        

          Max(a, b)  // a、b 都是 int
          Max<>(a, b)  // 空尖括号
          Max(3.0, 4.0)  // 两个 double
          Max(5.0, 6.0, 7.0)  // 三个参数
        

        

      


      
把上面几种调用连起来运行，输出就一目了然了：


      

        
main() 中的调用
          


int a = 1, b = 2;
cout << Max(a, b)   << endl;   // 规则①：普通函数完全匹配 → 选普通函数
cout << Max<>(a, b) << endl;   // 规则③：空<> → 强制走模板

cout << Max(3.0, 4.0) << endl; // 规则②：模板生成 double 版更合适

cout << Max(5.0, 6.0, 7.0) << endl; // 参数个数只能匹配三参模板

      


      

        为什么 Max(3.0, 4.0) 不去调用那个 int Max？
        

          
3.0 和 4.0 是 double。若硬要调用 int Max，
          就必须把 double 强制转换成 int——这会截断小数，是"有损"的，编译器认为不划算。
          而模板可以生成一个专门处理 double 的 Max，无需任何转换，显然更好。
          这就是规则②"更好的匹配"的含义。

8重要注意事项：模板不做自动类型转换

      
这是一个极易踩坑、必须记住的点。


      

        
🚧

        

          函数模板要求类型严格匹配，不会做自动类型转换；而普通函数可以。
        

      


      
看这个调用（接着 example20-3）：


      

        
类型不一致时会发生什么
          


cout << Max('a', 100) << endl;
// 'a' 是 char（值 97），100 是 int —— 两个类型不同
//
// 模板 T Max(T,T) 要求两个参数"同一个 T"，char 和 int 对不上 → 不匹配
// 普通函数 int Max(int,int) 可以把 'a' 自动转成 97 → 匹配成功
// 结果：调用普通函数，返回 max(97, 100) = 100

      


      

        
💥

        

          
思考：如果把普通函数删掉呢？

          那么只剩模板。Max('a', 100) 里 char 和 int 无法匹配同一个 T，
          模板也不做自动转换 →  编译直接报错。这说明模板的"严格"是一把双刃剑。

9多个类型参数与"返回值类型"的技巧

      
当一个模板需要好几种类型时。


      
模板可以有多个类型参数。比如一个通用加法：两个操作数类型不同，返回值类型也可以自定：


      

        
example20-4.cpp · 多类型参数
          


template<typename RT, typename T1, typename T2>
RT Add(T1 a, T2 b)
{
    return static_cast<RT>(a + b);   // RT = 返回类型 return type
}

      


      
调用时可以把三种类型全部显式写出来：


      

        
调用方式对比
          


// 全部写出：返回类型, 参数1类型, 参数2类型
cout << Add<double, char, float>('a', 100.0f) << endl;  // 'a'=97, 97+100=197

// 只写返回类型，其余交给编译器推导
cout << Add<double>('a', 100.0f) << endl;               // T1、T2 自动推导

      


      

        
🧩

        

          
为什么"返回类型"要放在第一个？

          编译器能从实参推导出参数的类型（T1、T2），
          但推导不出返回类型 RT——因为返回类型不在参数里，无从猜起。


          C++ 给出一个"不完美但实用"的方案：把需要显式指定的返回类型 RT 放在模板参数的第一位。
          这样调用时只需写 Add<double>(...)——第一个填 RT，剩下的 T1、T2 让编译器自动推导即可。
        

      


      

        如果把 RT 写在最后会怎样？
        

          
如果模板写成 template<typename T1, typename T2, typename RT>，
          那么你就没法只指定返回类型了：想指定第三个 RT，必须先把前两个也写出来，
          否则编译器无法推导 RT，直接报错。所以"把要手动指定的类型放前面"是一条实用经验。

        

      

    


    
    

      
10总结与终极自测

      
把今天的收获串成一条线。


      

        
要点一句话记住

        
本质函数模板 = 具有相同行为的一族函数，写一次可生成 N 个。

        
语法template<typename T> 给泛指类型 T "上户口"。

        
调用自动推导（Swap(a,b)）或显式指定（Swap<int>(a,b)）。

        
编译器按用到的具体类型实例化真实函数，会进行两次编译。

        
重载①优先普通函数 ②模板更优则选模板 ③空 <> 只走模板。

        
坑模板不做自动类型转换，要求类型严格匹配。

        
多参数需要手动指定的类型（如返回类型）放最前面。
