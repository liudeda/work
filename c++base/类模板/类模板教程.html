先热个身：还记得函数模板吗？template<typename T> 声明一个"泛指类型 T"， 编译器在你调用时按具体类型"生成"真正的函数。这一课，同样的 template<typename T> 会被我们写在 class 前面。语法上，几乎没有新东西。

1为什么需要类模板？先想一个工程问题

类本就是为了复用而生。模板能让复用更上一层楼。

C++ 相比 C 语言最大的进步，就是引入了面向对象，而类正是这种思想的载体。 学数据结构时你会发现，很大一部分类是用来存储和组织数据的——比如数组、链表。

现在思考一个问题：一个单链表，用来存 int 和用来存 double， 在算法上有区别吗？插入、删除、遍历的逻辑，会因为元素是整数还是小数而不同吗？

🧩
答案是：没有任何区别。我们实现数据结构时，根本不关心元素到底是 int、 double 还是 long，只把它们统一看成"数据元素"。

那么问题来了——做工程时，难道要为 int 写一套链表，为 double 再写一套， 为每一个自定义类型都各写一套？这些代码算法完全一致，毫无创造性，纯属体力活：

噩梦：为每种类型复制一份 
class IntList   { /* 一整套增删改查……只为 int   */ };
class DoubleList{ /* 一整套增删改查……只为 double，逻辑一模一样 */ };
class StudentList{ /* 又是一整套……为自定义类型 Student */ };
// 类型越多，重复越多。而且每一份都要单独测试、单独维护 😫
🚀
C++ 的答案：把模板思想用到类上
我们完全可以创建一种"只关注功能、不关心具体数据类型"的类。写一次， 就能服务 int、double 乃至任何自定义类型。这就是 类模板。
💼
课堂上的一句大实话
很多人加班无非两件事：工作量太多 和 bug 太多。 代码复用（面向对象 + 模板 + 泛型编程）正是对付"工作量多"的利器——写得越少，要测试和维护的也越少。

2类模板的语法：把 template 写在 class 前面

语法上几乎没有新东西，还是那两个老朋友：template 与 typename。

类模板的声明方式和函数模板如出一辙：在类的前面加一行 template<typename T>， 类就变成了类模板。我们以一个简单的运算类为例——它只负责两个数的加法和减法：

example21-1.cpp · 一个运算类模板 
template<typename T>          // ← 告诉编译器：接下来是泛型，泛指类型叫 T
class Operator
{
public:
    T add(T a, T b);          // 成员函数也能用 T
    T minus(T a, T b);
};

逐句拆解编译器"听到"的话：

你写的编译器的理解
template"哦，你要声明一个模板了。"
<typename T>"这个模板里操作的泛指类型叫 T。"
class Operator"原来你想把模板思想用到类上，那我帮你做一个类模板。"
📝
除了多出 template<typename T> 这一行、把原来的具体类型替换成 T 之外， 其它一切都和普通类的写法完全一样。public、成员函数、成员变量……老规矩不变。 （typename 换成 class 也可以，名字 T 也能改成任何你喜欢的。）

这个运算类的成员函数，我们把它写在类外面（工程里常这么干）。注意：因为它属于类模板， 每个成员函数在类外定义时，自己也要带上 template<typename T>， 并且要用 Operator<T>:: 限定它属于哪个类：

类外定义成员函数 
template<typename T>               // 成员函数本质上也是一个模板
T Operator<T>::add(T a, T b)       // Operator<T>:: 限定它属于哪个类模板
{
    return a + b;
}

template<typename T>
T Operator<T>::minus(T a, T b)
{
    return a - b;
}
⚠️
新手最爱漏的两处
① 每个类外成员函数前都要写 template<typename T>； ② 限定符必须是 Operator<T>:: 而不是 Operator::。 少了任何一处，编译器都会不认识 T 而报错。

3如何使用它？必须"显式指定"类型

这是类模板和函数模板一个关键的不同点。

函数模板有两种用法：让编译器自动推导，或者显式指定。 类模板呢？回忆一下——既然它们用的是同一套编译机制，是不是也能自动推导？

🚫
不行！类模板必须显式指定类型
创建对象时，必须用 Operator<int> 这样把类型写清楚，编译器不会替你推导。
正确：显式指定类型来定义对象 
Operator<int>    op1;   // T 变成 int，op1 专门处理 int 的加减
Operator<double> op2;   // T 变成 double，op2 专门处理 double 的加减

Operator op3;           // ❌ 编译错误！缺少模板参数，编译器不知道 T 是什么

为什么不能自动推导？

假设允许 Operator op1; 这样写。请问——op1 是处理什么类型加减法的对象？ 你说不出来，编译器更说不出来。定义对象时还没有任何实参可供推断， 这会带来无法消除的二义性 / 模糊性。所以 C++ 干脆规定：类模板老老实实写清类型。

👍
其实这样更好——Operator<int> op1; 一眼就知道它是干嘛的，代码清晰，便于日后维护。

完整示例（配套源码 example21-1）

      
把类模板、类外成员定义、以及使用组合起来。点 ▶ 运行 看看结果：


      

        
example21-1.cpp
          


#include <iostream>
using namespace std;

template<typename T>
class Operator
{
public:
    T add(T a, T b);
    T minus(T a, T b);
};

template<typename T>
T Operator<T>::add(T a, T b)   { return a + b; }

template<typename T>
T Operator<T>::minus(T a, T b) { return a - b; }

int main()
{
    Operator<int>    op1;   // 专门处理 int
    Operator<double> op2;   // 专门处理 double

    cout << op1.add(5, 4)      << endl;   // 5 + 4  = 9
    cout << op1.minus(4, 5)    << endl;   // 4 - 5  = -1
    cout << op2.add(1.3, 0.01) << endl;   // 1.3 + 0.01 = 1.31
    cout << op2.minus(0.01, 1.3)<< endl;  // 0.01 - 1.3 = -1.29
    return 0;
}

      


      

        
🔎

        

          op1 是 Operator<int>，所以 op1.add(5,4) 返回 int，结果是 9；
          op2 是 Operator<double>，所以 op2.minus(0.01,1.3) 返回 double，结果是 -1.29。

4编译器如何处理类模板？（与函数模板一致）

      
C++ 用同一套机制处理函数模板和类模板——两次编译。


      
和函数模板完全一样：编译器根据"类模板 + 你指定的具体类型"，在内部生成一个个
      真真正正、互不相同的类。这个过程就是类模板实例化。


      

        
🧠

        

          
类模板会被"两次编译"

          
    
            
  1. 第一次——在类模板定义处，只对模板代码做词法/语法检查，并不生成任何真实代码。
    2. 
            
  2. 第二次——在你用具体类型使用它时，才根据模板生成真正的类，再对生成的类编译、链接。
    3. 
          

        

      


      
换句话说，全局函数模板和类模板，在 C++ 编译器眼里是同一套处理方式，没有任何区别。
      记住"两次编译"这个结论——它是理解下一章那个"链接失败之谜"的钥匙。

5工程化第一步：声明与定义分离

      
课堂随手写没问题，产品代码要讲规范。


      
前面我们把成员函数写在了类外——这是工程里的好习惯：类的声明放一处，
      成员函数的实现放另一处，结构清晰。对普通类，我们通常把声明放进 .h、
      把实现放进 .cpp。那类模板是不是也照搬？


      
先看把声明和实现放在同一个文件里、只是分开写的形式（这一步是合法的）：


      

        
声明与实现分开（同一文件内，合法）
          


// —— 声明 ——
template<typename T>
class Operator {
public:
    T add(T a, T b);
    T minus(T a, T b);
};

// —— 实现（放到类外）——
template<typename T>
T Operator<T>::add(T a, T b)   { return a + b; }

template<typename T>
T Operator<T>::minus(T a, T b) { return a - b; }

      


      

        
📁

        

          放在同一文件里确实能得到一个合法的程序，但不利于大型产品代码的维护。
          真正的工程会把它们拆到不同文件里。而一旦拆分，就会撞上一堵"看不见的墙"——下一章的主角。
        

      

    


    
    

      
6谜题：拆成 .h + .cpp 为什么链接失败？

      
这是本课最烧脑、也最有价值的知识点。搞懂它，你对模板的理解会上一个台阶。


      
按普通类的经验，我们很自然地这么拆分：Array.h 放类声明，
      Array.cpp 放成员函数实现，main.cpp 里 #include "Array.h" 使用。
      结果一编译——链接错误（link error）：提示那些成员函数"未定义"。明明实现就在 Array.cpp 里，为什么找不到？


      
先看普通类：为什么它没问题

      

        

          
普通类 正常

          
1编译器编译整个工程的每个 .cpp（含 Array.cpp、main.cpp）。

          
2编译 Array.cpp 时，成员函数是普通函数，真实机器码当场生成。

          
3main.cpp 里调用这些函数 → 链接时去找那段机器码。

          
4机器码在 Array.cpp 里早已生成 → 链接成功。

          
✅ 找得到代码，程序正常运行

        

        

          
类模板 失败

          
1编译器同样编译每个 .cpp。

          
2编译 Array.cpp 时发现全是模板 → 只做语法检查，不生成任何代码（第一次编译）。

          
3编译 main.cpp 时要为 Array<int> 生成代码（第二次编译），但这里只 include 了 .h，看不到实现！

          
4链接时去找 Array<int> 成员函数的机器码 → 哪儿都没有。

          
❌ link error：符号未定义

        

      


      

        
🎯

        

          
谜底

          模板的第二次编译（生成真实代码）发生在使用它的那个文件（main.cpp）里。
          可 main.cpp 只 #include "Array.h"，根本看不到 Array.cpp 里的实现。
          而 Array.cpp 自己编译时，因为没人在这里用具体类型，也没生成任何代码。
          两头落空——于是链接器找不到符号。
        

      


      
解决办法：让"使用处"能看到实现

      
既然问题是"使用处看不到实现"，那就想办法让它看得到。最直接的做法：
      在使用处把实现文件一起 include 进来。


      
但直接 #include "Array.cpp" 会让人非常别扭——谁会去 include 一个 .cpp？
      所以工程约定：把类模板的实现文件改名为 .hpp（表示"这是模板的实现头文件"），
      并给它加上防重复包含的宏保护。最终形成这套经典结构：


      

Array.h   // 类模板的声明（含 #ifndef 保护）
Array.hpp // 成员函数实现；内部 #include "Array.h"
main.cpp  // 使用处：#include "Array.hpp"（不是 Array.h）
      


      

        
🔗

        

          
include 的本质就是"文本展开"

          #include 会把被包含文件的全部内容原样粘贴到当前位置。
          于是 main.cpp 里 #include "Array.hpp" → 展开了 hpp（含全部实现）→ hpp 里又
          #include "Array.h" 展开了声明。这样一来，main.cpp 里就同时拥有了声明和实现，
          第二次编译时自然能生成 Array<int> 的真实代码。链接成功！
        

      


      

        为什么叫 .hpp 而不是继续用 .cpp？
        

          
纯粹是工程约定俗成，为了让代码可读。.hpp 中的 h 表示它像头文件一样
          被别人 include，pp 暗示里面是 C++ 实现。你的同事一看文件名就懂：
          "哦，这是某个类模板的实现文件，是要被 include 的，不是拿去单独编译的。"
          它本质上仍是一个头文件，所以同样需要 #ifndef / #define / #endif 防止重复包含。

        

      


      

        
🧭

        

          
三条可落地的结论

          
    
            
  1. 类模板不能像普通类那样拆成 .h + .cpp 分开编译。
    2. 
            
  2. 正确姿势：声明放 .h，实现放 .hpp，使用处 #include 那个 .hpp。
    3. 
            
  3. 偷懒也行：声明和实现全部写在一个 .h 里——能用，但大型项目里不易维护。
    4.

7实战：把 Array 数组类升级为类模板

      
学以致用——把一个"只能装 int"的数组，改造成"什么都能装"的通用容器。


      
我们之前写过一个不错的数组类，但它只能处理某一种固定类型，"很不爽"。现在用类模板把它升级。


      
① Array.h —— 声明

      

        
Array.h
          


#ifndef _ARRAY_H_
#define _ARRAY_H_

template<typename T>              // ← 升级点：变成类模板
class Array
{
private:
    int mLength;
    T*  mSpace;                   // 元素类型用 T，而不是写死 int

public:
    Array(int length);
    Array(const Array& obj);
    int length();
    ~Array();
    T& operator[](int i);         // 下标访问返回 T&
    Array& operator= (const Array& obj);
    bool operator== (const Array& obj);
    bool operator!= (const Array& obj);
};

#endif

      


      
② Array.hpp —— 实现（注意每个函数都带 template 行）

      

        
Array.hpp（节选）
          


#ifndef _ARRAY_DEF_H_
#define _ARRAY_DEF_H_

#include "Array.h"                // 实现文件包含声明

template<typename T>
Array<T>::Array(int length)
{
    if (length < 0) length = 0;
    mLength = length;
    mSpace  = new T[mLength];      // 用 T 分配空间
}

template<typename T>
int Array<T>::length() { return mLength; }

template<typename T>
Array<T>::~Array() { delete[] mSpace; }

template<typename T>
T& Array<T>::operator[](int i) { return mSpace[i]; }

// operator= / operator== / operator!= 同理，逐个加上 template<typename T>
#endif

      


      
③ main.cpp —— 使用（include 的是 .hpp！）

      
一份 Array，同时服务 int 和 double。点 ▶ 运行：


      

        
example21-2.cpp
          


#include <iostream>
#include "Array.hpp"     // ← 关键：include 实现文件 .hpp，不是 .h
using namespace std;

int main()
{
    Array<int> ai(5);                 // 一个能装 5 个 int 的数组
    for (int i = 0; i < ai.length(); i++) ai[i] = i + 1;
    for (int i = 0; i < ai.length(); i++) cout << ai[i] << endl;

    Array<double> ad(10);             // 同一套代码，装 double
    for (int i = 0; i < ad.length(); i++) ad[i] = (i + 1) / 100.0;
    for (int i = 0; i < ad.length(); i++) cout << ad[i] << endl;
    return 0;
}

      


      

        
🎉

        

          成就时刻：我们只写了一次数组类，它却能存 int、
          double，将来还能存结构体、自定义类。这就是类模板带来的复用威力。
        

      


      

        
🛠️

          如果你亲自编译遇到 link error，先检查两点：使用处是不是 include 的 .hpp？
          每个类外成员函数前是不是都带了 template<typename T>？
          九成的模板链接/编译问题都出在这两处。
        

      

    


    
    

      
8一个细节：只有被调用的成员函数才会被生成

      
编译器很"懒"，而这种懒是一种优化。


      

        
😴

        

          只有被真正调用到的类模板成员函数，才会被编译器生成可执行代码（第二次编译）。
          你没调用的成员函数，编译器就不为它生成代码。
        

      


      
这不是偷工减料，而是必要的策略：一个类模板理论上能实例化出无数种类型的版本，
      每个版本又有若干成员函数。如果不管用没用全都生成，代码会爆炸式膨胀。所以编译器选择——
      你用哪个，我才生成哪个。


      

        
🔬

        

          
一个有趣的副作用

          正因为"不调用就不生成代码、也不做第二次编译"，某个成员函数即使内部藏着只对特定类型才报错的写法，
          只要你从不调用它、且用的类型碰巧没触发问题，程序也能编译通过。这既是灵活性，也是隐蔽 bug 的温床——
          记住这个知识点即可。

9类模板特化：给某个类型"开小灶"

      
当通用模板对某种特殊类型不好使时，我们可以为它专门定制一份。


      
类模板很通用，但偶尔会遇到：某个特殊类型用通用版本处理起来不方便，甚至根本不合适。
      这时可以针对这个类型写一份特化（specialization）版本。先看通用版：


      

        
通用类模板 Test<T>
          


template<typename T>
class Test
{
public:
    T test(T v)
    {
        cout << "T test(T v)" << endl;          // 不管什么类型，都打印这句
        cout << "sizeof(T) = " << sizeof(T) << endl;
        return v;
    }
};

      


      
假设我们希望：当类型是 int 时，输出更直观地写成 int test(int v) 和
      sizeof(int)。于是给 int 写一份特化：


      

        
针对 int 的特化
          


template<>                 // ← 空的尖括号：告诉编译器"这是一个特化"
class Test<int>            // ← 特化谁？特化 Test 在 int 时的版本
{
public:
    int test(int v)
    {
        cout << "int test(int v)" << endl;
        cout << "sizeof(int) = " << sizeof(int) << endl;
        return v;
    }
};

      


      

        
🔑

        

          
特化的语法关键

          template<>（空尖括号）宣告"下面是一个特化"，
          Test<int> 指明"特化的是 Test 在 int 时的版本"。
          特化体里就可以用具体的 int 来重写实现了。
        

      


      
      

        
🧪 互动演示：编译器优先选谁？

        
给 Test<T> 传不同类型，看编译器选"通用模板"还是"int 特化"。

        

          Test<int>
          Test<double>
          Test<char>
        

        

      


      

        
example21-3.cpp · main()
          


int main()
{
    Test<int> t1;
    cout << t1.test(1) << endl;   // int 有特化 → 走特化版本
    return 0;
}

      


      

        
📌

        

          输出是特化版的 int test(int v) 而不是通用版的 T test(T v)，
          证明了一条重要结论：当存在匹配的特化时，编译器会优先选用特化，而不是通用模板。
        

      


      
特化的进阶用法：继承一个特化类

      
特化在工程上很有意义——我们甚至可以继承一个特化类，开发出自己的新类。
      而这个新类从使用者角度看，就是一个普通的类（不再是模板）：


      

        
继承特化类
          


class MyTest : public Test<int>   // 继承 int 的特化版本
{
    // MyTest 就是一个普通类了，天生具备 Test<int> 的能力
};

要点一句话记住

        
本质类模板 = 只关注功能、不关心具体数据类型的一族类，写一次可生成 N 个真实类。

        
语法在 class 前加 template<typename T>；类外成员函数每个都要带 template 行并用 类名<T>:: 限定。

        
使用必须显式指定类型：Operator<int> op;，不能自动推导（会产生二义性）。

        
编译器与函数模板同一套机制，两次编译：定义处查语法，使用处才生成真实代码。

        
工程化声明放 .h、实现放 .hpp，使用处 #include 那个 .hpp；不能拆成 .h+.cpp 分开编译。

        
按需实例化只有被调用的成员函数才会被生成代码。

        
特化template<> class X<具体类型> 给特殊类型定制；有特化时编译器优先用特化。
